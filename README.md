# 伴圆 CRM · AI 操作型 CRM

**让 AI 根据使用人授权的资料，整理客户、补齐过往记录，并形成未来行动与日程。**

人不必反复把已经聊过、做过的工作再填一遍。把获准使用的沟通、听记、录音转写、PPT、报价和合同交给 AI，AI 识别客户与事项、梳理推进过程，再通过 CRM 的应用服务保存数据、提出行动、推进流程和查询结果。人负责授权资料、核对重要事实及作出应由本人决定的审批。

> **仓库内业务资料全部是虚构的“天雨阀门”演示数据。** 公司、人员、客户、金额、沟通内容、合同和审批均为合成样例，不含真实企业的业务资料、数据库、日历、聊天、密码或连接凭证。演示账号统一密码 `12345`，仅用于隔离测试帐套。

## 从日常工作到可查询的经营过程

```mermaid
flowchart LR
  A[用户授权的资料] --> B[AI理解与提取证据]
  B --> C[识别客户及项目]
  C --> D[过去的沟通与工作记录]
  C --> E[未来行动与日程]
  D --> F[CRM应用服务与数据权限]
  E --> F
  F --> G[流程核对与实际执行]
  G --> H[回执 明细和统计]
```

- **做过方案与PPT**：形成线索，保留客户、需求和资料来源。
- **做过报价或反复改报价**：形成商机及版本记录，区分内部工作与实际客户沟通。
- **准备了合同**：保留方案确认及未签草稿；签章、验收、开票与到账分别取证。
- **有待推进或待收款事项**：生成下一步、负责人、内部计划日期和本地日程，完成后补实际结果。
- **沟通在钉钉、飞书或会议里**：由获授权的外部AI和连接工具读取资料，CRM承接结构化记录；组织、日程和原生审批按各自配置与权限同步。

使用人选择自己的 AI 工作入口。CRM负责业务对象、权限、状态、流程和审计；外部智能体通过HTTP/MCP及受控资料导入服务操作。系统不会因为安装了软件就获得全部聊天或文件权限，也不会把 AI 建议当作审批决定或到账事实。当前可用接口与授权方式见[能力说明](docs/AI_OPERATED_CRM.md)。

## 丰富过程，减少无意义的数据堆积

天雨2.0把原来的大批基础数据缩小约70%—75%，另补12个有上下文的故事、58份虚构授权资料、36项AI行动及对应本地日程。它们覆盖标准件、定制件、直销、渠道甲方、长周期项目、合同草稿、分期回款、验收尾款、续费价格冲突、历史资料缺合同及资源不足掉单。

| 基础对象 | 2.0数量 | 相较旧版 |
| --- | ---: | ---: |
| 客户 / 联系人 | 15,000 / 6,000 | 减少75% |
| 商机 / 跟进 | 2,400 / 9,000 | 减少约70%—73% |
| 合同 / 订单 | 360 / 240 | 减少70% |
| 分期计划 / 开票 / 收款 | 960 / 660 / 182 | 保留金额核对链路 |
| 项目 / 里程碑 / 任务 | 84 / 336 / 336 | 减少65% |
| 角色账号 | 14 | 管理员、老板、主管、销售、交付及财务 |

新增的故事、审批处理和AI行动在上述基础上追加；准确数量和SHA见[数据清单](demo/tianyu/manifest.json)及[验证记录](demo/tianyu/verification.json)。

## 36类流程和246张有内容的审批

客户建档、领取与分配、报价折扣、技术评审、图纸变更、试制、分批交货、质量整改、验收收尾、质保金、渠道金额、续费、历史补录、资源放弃和AI行动核对均有示例。

每张申请包含客户、关联单据、规格及图纸、数量、付款条件、变更前后、风险和执行依据等16项内容。示例包括顺序审批、或签、会签、待审、通过、退回补充、撤回、重提、部分已审和转审。通过内部通用事项审批并不等于已发货、开票、收款或向外部发送。见[审批演示手册](demo/tianyu/APPROVAL_GUIDE.md)。

## 系统业务能力

客户与去重、公私海、客户分配及整体交接、部门及下属数据权限、商机看板、报价版本、合同审批、订单、交付任务、里程碑、验收整改、售后、收款登记与核销、合同和开票未收统计、日期和人员范围、钻取和正反序排序均有应用服务与网页入口。

本地B/S及手机H5；每个公司独立MySQL数据库、连接账号和密钥。钉钉组织、本人日程/待办、原生审批各有配置和对照。真实企业接入取决于实际授权与联调；浏览器可保留人工操作入口。

## 本地使用

需要 Node.js 24、pnpm 11.25.0、MySQL 8。首次安装需要联网。

```sh
pnpm install --frozen-lockfile
pnpm --filter @partneros/database generate
pnpm build
pnpm local:start
```

打开 `http://localhost:3000`。本机管理入口 `http://localhost:3000/__accounts` 用于创建独立公司数据库；正式公司初始化为空。新建编码 **TIANYU**、名称 **天雨阀门**、用途 **测试** 的空帐套，再按[天雨安装说明](demo/tianyu/README.md)初始化。既有1.0演示数据请先备份，使用新测试库安装2.0，不覆盖真实公司。
