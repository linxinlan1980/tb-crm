# 伴圆 CRM 演示版 v0.2

本轮交付是本地演示与数据测试系统。财务页面明确标记暂无处理功能；真实企业连接的完成状态单独记录。

## 启动与四角色

本机双击仓库中的 `启动演示.command`，或执行 `pnpm demo:start`。打开 http://localhost:3000。启动器仅绑定本机，检查数据库并应用已提交迁移，启动API与前端静态服务。首次准备源码需先执行 `pnpm install --frozen-lockfile`、配置 `.env`、迁移与 `pnpm demo:seed`、`pnpm build`。

| 登录角色 | 账号 | 视图与操作 |
| --- | --- | --- |
| admin | admin | 管理本租户用户、组织、权限查看、审计、审批设计器、集成连接 |
| 销售主管 | manager | 团队数据、客户分配、商机与业务单据、审批 |
| 销售 | sales | 本人私有数据、公海摘要及领取、销售到项目主线、发起审批 |
| 老板 | boss | 全公司经营数据与下钻、最终审批；业务编辑默认关闭 |

密码由本地 `SEED_ADMIN_PASSWORD` 初始化。本机账号说明在 Git 忽略的 `.local/演示账号.md`，不在公开仓库保存可用密码。另有销售测试身份用于验证本人、同部门与跨部门的不同可见范围。

## 建议的20分钟演示

1. 老板登录：查看经营驾驶舱、销售漏斗、合同额和演示应收数据，点击指标下钻。
2. 销售登录：浏览本人客户、公海受限摘要；领取一条公海记录。客户详情显示联系人、商机、合同、项目和跟进。
3. 新建线索并转为客户；新建联系人和跟进；创建行动计划并完成。
4. 新建商机，填写金额与需求，推进阶段；使用产品明细生成报价金额。商机看板和列表使用同一份数据。
5. 新建合同，关联客户/商机，提交审批。合同含税金额与税额使用Decimal计算。
6. 主管登录：审批合同的当前节点；金额达到演示阈值10万元后流转老板。老板通过后，销售确认签约。
7. 从已签合同创建订单和交付项目；订单、项目分别审批。订单确认后交付；项目完成四个里程碑，再填写验收说明。
8. 打开回款计划查看签约后生成的演示计划；打开财务功能展示，核对“演示系统，暂无功能”和禁用按钮。
9. admin登录审批设计器：创建通用事项或合同流程，添加表单字段、审批节点与金额条件，排序节点，保存草稿、预演并发布；再由销售提交申请。
10. 打开AI工作台：生成明确标注的规则摘要，实际调用客户查询能力并查看执行编号。查看站内通知与业务审计。

审批流支持顺序节点、金额条件、指定人、唯一可解析角色及部门负责人。设计器只列出具备通过及驳回权限的可用人员；多名角色候选需要改为指定人，不会任意选人。缺少流程/有效审批人、申请人审批自己、越过当前节点均会阻止操作。表单字段可为文本、数字、日期；已发布流程编辑生成新草稿版本，既有实例保留提交时快照。

## 数据与复演

标准数据包含40个客户、60个联系人、20条线索、24个商机、12份合同、8个已签业务的订单/项目、24条回款计划，以及跟进、任务、行动和合成财务记录。日期按初始化当天生成，避免逾期场景过时。列表与经营指标按角色过滤，不承诺各账号看到相同数量。

- `pnpm demo:reset`：新建并初始化一个干净的本地演示副本，成功后切换 `.env` 的数据库地址；旧库保留。重新启动演示系统后使用新副本。
- `pnpm demo:test`：新建独立测试副本、迁移、灌入演示数据，再执行完整真实数据库测试；不会修改演示库。
- `pnpm check`：类型、lint、自动化测试、构建。

新建副本需要本机数据库建库权限。当前本机使用隔离安装的MySQL 8.4.11；其他环境可配置 `DEMO_ADMIN_DATABASE_URL` 或本机 `MYSQL_ROOT_PASSWORD`。脚本只接受本地 `tb_crm_demo` / `tb_crm_test` 及其时间戳副本，不包含删库操作。历史连接记录仅保存在 `.local/database-history.json`。

## 智能体接入

MCP Streamable HTTP：`POST /api/v1/mcp`，使用当前用户的有效Bearer访问令牌。当前7个只读工具：`customer.search`、`customer.get`、`workspace.list`、`workspace.get`、`workspace.overview`、`workspace.schema`、`approval.pending`；另有 `crm://capabilities` 和 `crm://approval-capabilities` 资源。采用受维护的SDK v1，协议协商至2025-11-25；独立OAuth委托凭证尚未实现。

业务HTTP契约：`GET /api/v1/workspace/schema`；审批HTTP契约：`GET /api/v1/approvals/schema`，按当前角色过滤。查询 `/workspace/{kind}`，详情 `/workspace/{kind}/{id}`；创建POST、编辑PUT、业务动作POST `/{action}`。写入使用 `requestKey`，更新/动作必须携带详情中的 `updatedAt` 为 `expectedUpdatedAt`。参数不接受调用方注入租户或操作人。写入使用事务、持久化幂等记录和审计；重复键与不同请求内容冲突时拒绝。

MCP不开放写入。网页业务写入与能力目录共用WorkspaceService；金融处理写入关闭。旧原型业务REST入口已返回503并从OpenAPI文档隐藏，避免绕过新边界。

## 当前明确限制

- 财务仅合成数据展示；不执行真实开票、收款、核销、凭证或银行对账。
- AI摘要为规则生成，未接大模型；自治智能体和独立委托授权未实现。
- 审批设计器未提供并行会签、嵌套条件、加签转审和外部审批双向回调。
- 钉钉/飞书支持真实令牌、部门及成员预览请求；尚无企业凭证，未进行真实企业联调。免登、自动导入、消息发送和双向审批同步尚未开放。
- 生产部署、备份恢复、性能容量、完整移动适配及整体安全验收不属于本次已验证结果。
