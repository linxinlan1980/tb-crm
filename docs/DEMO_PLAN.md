# 演示版 v0.2 建设计划

计划日期：2026-10-31。负责人：Codex；产品验收：项目所有者。
状态：计划已制定，尚未实现本计划列出的新功能。

## 目标与边界

用户要求以一天内交付可完整演示、可反复做数据测试的CRM为目标，允许暂缓复杂内容。用户报告剩余用量为“81”，单位和实时余额未知；不把用量当作可保证的开发时长。一天是冲刺目标，完成以验收证据为准。按工作批次推进，不虚构完成时间或百分比。

交付目标：四类角色真实登录，主要模块有完整导航及数据，销售到交付回款的一条主线可以实际操作，数据落库且前后联动；可初始化、重置、再次演示。沿用NestJS、React、MySQL和已有原型，避免重构换框架。演示版不等于生产验收。

## 四角色基线

| 角色 | 演示账号名（计划） | 默认入口和数据范围 | 允许的业务 | 限制 |
| --- | --- | --- | --- | --- |
| admin | admin | 系统管理；当前租户全部演示数据 | 用户、角色、部门、字典、审计、演示初始化与重置 | 重置仅显式演示环境可用，需确认；不授予跨租户访问 |
| 销售主管 | manager | 团队工作台；本部门客户和业务、公海 | 分配客户、团队跟进、商机管理、一级审批 | 无其他部门私有数据、无账号权限配置 |
| 销售 | sales | 个人工作台；本人业务、可领取公海的受限摘要 | 线索、客户、联系人、跟进、商机、提交报价合同、查看本人回款 | 不看其他销售私有数据；不审批本人单据、不改全局配置 |
| 老板 | boss | 经营驾驶舱；当前租户全部业务 | 营收/商机/回款/逾期分析、业务下钻、最终审批 | 默认不改系统权限、不直接改销售业务记录 |

以上作为本轮实施默认规则。前端导航、页面按钮、后端操作权限、记录可见范围和能力接口必须一致。老板沿用现有gm业务角色方向，不能直接复用super_admin。演示数据另设第二部门和其他销售测试身份，用于证明越权被拒绝。密码由本地环境生成/注入，不把可用密码提交公开仓库。

## 本轮功能范围

| 模块 | 本轮必须可演示的行为 | 暂缓内容 |
| --- | --- | --- |
| 登录/系统 | 四角色账号、退出、角色专属首页、最小用户管理、部门与权限配置查看 | 自定义权限设计器、SSO、钉钉免登 |

| 线索/客户 | 线索建档和转客户、客户和联系人增改查、公海领取/退回/主管分配 | 模糊合并、高级回收策略、批量规则引擎 |
| 跟进/任务 | 写跟进、下一步计划、完成待办；客户详情显示时间线 | 日历双向同步、自动外发消息 |
| 商机/报价 | 商机列表/看板/详情、阶段推进、产品明细与报价汇总 | 多币种、多版本复杂折扣审批 |
| 合同/审批/订单 | 基础合同、固定主管/老板审批、驳回再提交、签约、关联订单 | 通用流程设计器、电子签章、复杂变更/撤销补偿 |
| 项目/交付 | 合同关联项目、任务、里程碑、演示验收记录 | 资源排程、成本分摊、复杂证据文件处理 |
| 回款/发票/账龄 | 回款计划、手工登记演示收款、开票记录、未收/逾期统计 | 真实税务开票、银行核销、会计凭证、复杂部分冲销 |
| 通知/审计 | 站内待审批/待办提示、关键动作审计 | 短信/邮件/钉钉实际发送 |
| AI/智能体 | 有权限的业务查询、客户摘要/待跟进建议展示、可验证的只读能力调用示例 | 任意自主操作、多智能体编排、委托授权体系、金融写工具 |

AI摘要无模型密钥时用明确标注的规则摘要，不能伪装成大模型生成。智能体只读能力在最后批次增加轻量MCP适配；若时间不足，优先保证现有版本化HTTP能力可被真实脚本调用，并明确未实现MCP。不增加外部服务依赖阻塞演示。

## 演示数据与复演

计划提供确定性种子：2个部门、4类角色、至少2名销售，约40个客户、60个联系人、20条线索、24个商机、12份合同/订单、8个项目、24条回款计划。数量是测试集目标，可在不减少场景覆盖的情况下调整。所有业务单位、人员及金额均为合成演示数据。

必须覆盖公海/私海、本人/他人/跨部门、不同商机阶段、审批中/驳回/通过、未回款/部分回款/逾期、项目进行中/验收。使用固定基准日期或统一可配置日期生成逾期场景，避免演示数据随时间失效。种子同时提供预期统计值，验证汇总金额和漏斗。

提供开发启动说明、初始化命令、仅演示环境可用的重置命令、四角色账号说明和15—20分钟演示脚本。重置入口只针对明确配置的演示库，不自动删除用户已有资料。

## 数据与功能验收标准

1. 四角色分别使用凭证登录；切换账号后不残留上个账号缓存。隐藏菜单之外，直接访问接口也执行相同限制。
2. 主管只看团队私有业务，销售只看本人私有业务；公海仅开放领取所需字段。老板看本租户全部业务，admin管理本租户；均不得跨租户。
3. 从新线索创建客户、联系人、跟进、商机、报价、合同审批、订单、项目、回款，刷新页面和重启服务后数据仍在。
4. 金额用Decimal计算；合同/回款/未收/账龄口径固定。已收不超计划、负金额被拒绝、重复请求不重复记账。
5. 同一客户同时领取只成功一次；非法状态推进/越权审批被拒绝；新增写入采用事务，关键动作有审计。
6. 主要页面具备加载、空数据、错误、校验反馈；未实现功能明确标注或移除操作入口，无伪造成功提示。
7. 真实MySQL集成检查与浏览器四角色主线验收分别记录。pnpm check通过不替代数据库和界面验收。
8. 使用相同演示数据重置后可再次跑通，并有运行方式、已知限制、测试记录与演示说明。

## 截止前的取舍顺序

首先后移：真实外部集成、通用审批引擎、复杂财务、自治智能体、完整MCP授权、多币种、移动端精修、性能专项。
其次简化：批量导入、复杂图表、高级筛选和非关键编辑项；保留必要的详情/列表和一条真实业务主线。无法实现的操作不做假按钮。
始终保留：四角色登录与后端权限、关键链路落库、金额和状态一致性、演示数据可重置、测试与运行说明。不以“演示”为由取消这些检查。

## 依赖与当前风险

- 本机尚无可用MySQL/Docker；D1需建立本地可运行数据库。已有GitHub CI临时MySQL可供集成验证，但不能替代本地演示环境。
- 原型多数模块尚未逐一验证，跨模块联调可能暴露额外缺陷；优先修主线，非关键项明确暂缓。
- 用量实时余额和重置时间无法由当前工具读取；用户提供“81”不转化成可保证的时间或token数量。
- 采用本地演示作为默认交付方式；公网部署、域名及生产上线不列入本轮必需范围。
