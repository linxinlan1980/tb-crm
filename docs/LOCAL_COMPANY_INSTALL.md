# 本地安装、公司帐套与外网配置

适用版本：0.3.0候选；本地B/S，电脑浏览器与手机H5共用业务服务。正式公司从空业务数据开始。完整生产验收尚未完成。

## 安装和启动

需要Node.js 24、pnpm 11.25.0和本机MySQL 8。先在项目根目录执行：

```sh
pnpm install --frozen-lockfile
pnpm --filter @partneros/database generate
pnpm local:start
```

本机已经安装原生MySQL运行环境时，也可双击根目录`启动系统.command`。启动器先构建代码，然后开启公司网关；不会灌入样例数据，也不会重设已有密码。手工启动时关闭终端会停止网站；新增[macOS登录守护与整套恢复](operations/LOCAL_RECOVERY.md)，须按说明另行安装服务。

其他安装机器须由运维通过私有环境变量`ACCOUNT_ROOT_DATABASE_URL`提供本机MySQL安装连接，例如`mysql://PROVISIONER:PASSWORD@127.0.0.1:3306/mysql`，账号需要建库、建用户和授予目标库权限。密码不得提交Git。已配置外部数据库时启动器不启动本机捆绑MySQL。此批实际验证macOS原生MySQL和CI测试脚本；既有单公司Docker安装与新多公司网关不是同一部署方案，不能互称通过。

打开`http://localhost:3000/__accounts`，选择本机`.local/accounts/management-token.txt`或输入文件内的口令。管理口令只用于服务器本机，员工账号不能管理服务器上的其他公司。

## 新建公司

填写2—30位大写公司编码、名称及用途（正式业务或测试验证），点击“创建独立帐套”。系统串行创建独立MySQL数据库、独立连接用户、独立登录及加密密钥，执行迁移，再创建四种角色、管理部门和一个管理员。客户、商机、合同、项目和收款等业务表为空。首个管理员初始密码仅在创建结果及本机账号说明文件显示；重复公司编码会被拒绝，不覆盖已有数据。

每个公司运行独立API进程，内部端口默认4300起且只监听127.0.0.1。公共网页/网关默认3000端口，可供局域网访问。路由使用公司编码，身份仍由该公司独立令牌、会话和实时权限校验；公司编码不是授权凭证。工作进程禁止读取根目录全局`.env`，避免跨公司继承密钥和第三方连接设置。

角色为管理员、销售主管、销售、老板。系统管理中创建实际员工，并分配角色和部门；没有预设销售/主管/老板的虚构员工。默认最多10个帐套是安装配置上限，不是经过容量压测的承诺。

初始化失败时保留失败记录和隔离资源，显示“初始化未完成”，不删除其他帐套；需运维核查本机初始化日志。尚无失败帐套一键修复、删除、跨版本批量升级或自动迁移提升。未运行的正常帐套可点击“启动服务”。

## 访问与切换公司

本机：`http://localhost:3000`。局域网地址由帐套管理页面按当前网卡显示，IP改变后以页面为准。手机与服务器同网，使用浏览器输入局域网地址；输入公司编码、自己的用户名和密码。390像素布局已验证；仍需在实际手机和Wi-Fi环境验收。

右上角账号菜单“切换公司帐套”先撤销当前会话，再进入登录页；每个标签页单独保存当前公司登录状态。个人密码、会话撤销在“账号与安全”；人员维护在系统管理。

## 外网访问配置页面

入口为“系统管理 → 公司帐套 / 外网配置 → 打开外网配置页面”，或服务器本机`http://localhost:3000/__accounts#remote`。局域网/外网不能打开管理控制面，需要在服务器本机使用独立管理口令。

页面提供：

1. 暂不启用、HTTPS反向代理、VPN内HTTPS三种方式。
2. HTTPS域名/IPv4及可选端口，拒绝含密码、路径、查询参数或无效主机名的地址。
3. 保存并回载入口配置；始终区分“未配置”和“已保存、待外部验证”。
4. 本机公司服务就绪检查，不向任意外部地址发起服务器探测。
5. 根据已保存地址生成Nginx HTTPS代理文本，保留Host、转发至本机网关，并禁止转发`/__accounts`。
6. 域名/证书、代理安装、外部手机网络验收的操作顺序。

保存配置不会自动安装Nginx、开路由器端口、购买域名、签发证书或建立VPN。运维应先配置有效证书，修改模板证书路径，运行`nginx -t`后再加载；模板本批未在真实域名/证书环境应用。MySQL和公司内部API端口只保留本机访问。配置外网后，用手机关闭Wi-Fi实测登录、公司隔离和业务读取；本批没有外部入口，不报告外网联通通过。

## 备份与恢复边界

每家公司单独备份：

```sh
node deploy/company-backup.mjs COMPANY_CODE /absolute/path/company-20261115.crmbackup
```

需本机MySQL客户端；自定义安装可设置`MYSQL_BIN_DIR`。命令只加载所选公司的凭证，以一致性转储生成AES-256-GCM加密归档，拒绝覆盖同名文件。备份密钥在该公司本机配置中，请另行离线妥善保存；代码仓库、数据库文件本身不等于完整备份。

现有恢复工具只恢复至新库，不覆盖原库，检查版本指纹并轮换会话密钥。新增[整套本机恢复工具](operations/LOCAL_RECOVERY.md)，认证后恢复全部公司到新库/独立账号并核对注册表；须离线核对后明确切换，不自动替换原网站。完整跨机器断电灾备及恢复界面仍未验收。首次正式公司加密备份已生成并完成解密认证校验；不是整机灾备演练通过。

两个帐套及丰富测试资料的使用见[正式/测试帐套说明](TEST_COMPANY_GUIDE.md)，组织和客户归属去重见[规则说明](ORG_CUSTOMER_QUALITY.md)。
