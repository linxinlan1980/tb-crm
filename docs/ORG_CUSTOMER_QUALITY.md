# 公司组织、客户归属与去重

## 简化组织模型

每个公司独立帐套；公司内配置部门树、上级部门、负责人和人员。借鉴本机WorkBuddy组织人事PRD的组织归属、改动留痕和权限校验思路，不复制薪酬、考勤、编制等HR模块，也不修改HR工程。

系统管理中可建部门、指定上级、先将人员划入部门再设负责人，创建/停用人员并分配角色。组织页显示真正的树形关系及负责人名称。服务端禁止循环引用、超过20层和指向无效上级；有有效成员或下级部门时不能停用。停用、调岗或改角色前须交接未完成销售、审批、交付及售后责任；已有会话按现有规则撤销。

四种预置角色可分配给人员：管理员管理公司配置；销售主管默认看本部门当前团队和公海；销售看本人及公海；老板看公司经营并按授权审批，不能编辑销售业务。角色页展示实际功能权限与数据范围。当前不开放自定义角色定义、任意字段权限或跨层级自动继承；部门树本身不会悄悄放大主管的数据权限。

## 客户与人员的关系

手工新建、线索转化的客户属于当前创建人，不能从请求正文伪造ownerId/tenantId。批量导入契约升级2.0，新导入客户也归当前导入人私海；若要进入公海，应显式退回。此前旧导入版本的公海语义保留为历史，不自动改写既有客户归属。

无下游销售业务的客户可从公海领取、退回、或由主管/管理员指定销售。主管分配候选只返回本部门有效销售；管理员可跨部门分配。分配提交仍重新检查客户可见范围、接收人资格与当前版本，不能靠修改前端请求跨部门分配。

已有商机、线索、合同、订单、项目等关联业务时，直接退回/分配会被拒绝，应从“客户导入 / 销售交接”先预检影响，再整体交接客户、相关销售归属和未完成销售工作。项目经理、历史作者和已完成任务不会被误改。客户详情、列表、联系人、财务和报表继续按实际可见关系读取，避免只改客户owner而丢失下游业务。

## 多维去重规则

|规则|处理|说明|
|---|---|---|
|客户全称标准化相同|阻止保存|全半角、空白、英文大小写归一；不静默合并|
|统一社会信用代码相同|阻止保存|证照号码归一后使用公司内唯一指纹；支持旧记录缺指纹的查重|
|名称或简称近似|提示人工核对|去标点及常见公司后缀，仅作为线索，不强行合并不同法人|
|企业电话相同|提示人工核对|归一常见号码格式和中国区号；共享总机可能属于不同主体|
|官网域名相同|提示人工核对|忽略协议、www及路径；共享集团网站不代表同一法人|
|地址和法定代表人均相同|提示人工核对|两个维度同时匹配；不以常见人名独自判重|

信用代码为可选字段，填写时校验18位字符格式；不代表已查工商真实性、不做证照OCR或外部工商查询。营业执照图片识别、境外登记号码及自动客户合并不在本批实现范围。

保存前页面会查重：硬重复返回主管核对；相似记录显示可见的名称与匹配原因，用户核对后可继续。权限外记录仅给受限提示，不返回客户ID、名称、负责人、电话或证照内容。手工写入、编辑、导入和线索转化仍在事务内重新检查硬重复；预检不是绕过服务端唯一校验的开关。CSV新增简称、信用代码、企业电话、法定代表人四列，支持现有库与文件内证照去重；提交前再次核对，失败不写入半批数据。

客户去重只在当前公司数据库内进行，不能读取其他公司的客户作为查重来源。查重预算为10000条，超出明确拒绝，不静默截断或宣称没有重复。

## 参考来源与取舍

Salesforce把匹配规则与重复处理规则分开，标准客户匹配包括网站和电话等组合维度；其标准行为不必然仅凭同名阻断。见[标准客户匹配规则](https://help.salesforce.com/s/articleView?id=matching_rules_standard_account_rule.htm&language=en_US&type=5)、[仅同名未必触发的说明](https://help.salesforce.com/s/articleView?id=000386375&language=en_US&type=1)。

Zoho说明唯一字段可用于手工、导入、API和转化等入口的重复控制，见[重复记录检查](https://help.zoho.com/portal/en/kb/crm/manage-crm-data/duplication-management/articles/check-duplicate-records)。本系统按产品负责人要求采用“同名/同证照硬拦截、其他维度提示”，并将创建人与归属关系、当前权限和事务校验统一在共享业务服务中；不是照搬某厂商界面或声称功能完全等同。
