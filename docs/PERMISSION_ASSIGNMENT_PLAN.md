# 下一批：客户分配、功能权限、数据权限及操作页面

2026-11-15产品负责人补充要求。优先级：钉钉组织同步收尾后，先完成本批，再推进日程与流程待办同步。本文保留原工程及验收计划；本批已实现范围、实测证据和限制以[操作说明](ACCESS_PERMISSIONS_AND_ALLOCATION.md)及进度顶部为准。下表为实施前盘点。

## 当前核对结果

| 范围 | 当前代码与页面 | 尚缺的闭环 |
|---|---|---|
| 客户归属 | 新建/导入客户归创建人；公海领退、主管/管理员分配、销售整体交接；客户操作有人员选择页 | 独立客户分配工作台、列表批量选择、分配前影响预览、人员名下客户反查、结果历史入口 |
| 人员角色 | 人员页可选择admin/销售主管/销售/老板四种角色；后端调岗/停用有责任交接检查 | 易用的人员权限总览、有效权限预览、人员与角色影响说明 |
| 功能权限 | 后端已有业务权限校验，角色权限页目前只读；旧角色写入入口明确停用 | 可保存的模块/操作矩阵及页面、后端共享授权、权限撤销与直接URL/MCP拒绝验证 |
| 数据权限 | 实际规则目前主要由四种角色决定：销售本人及公海、主管当前直接部门、老板/管理员公司；客户/报表等按服务过滤 | 可编辑的数据范围配置、指定部门/人员的明确设计、统一作用于列表/详情/搜索/统计/导出/智能体 |
| 钉钉人员 | 真实组织及对应关系已导入；新人员停用，未擅自授管理员权限 | 启用前角色、部门、有效功能与客户范围的检查入口；未核定部门人员的清晰提示 |

不能仅开放旧角色CRUD：其中仍有未经事务和输入约束复核的原型实现。也不能只修改角色表中的 `dataScope` 或隐藏菜单，现有部分业务授权按角色编码判断，须逐入口统一后才开放配置。

## 页面与操作

1. **客户分配工作台**：按部门、销售、私海/公海、未分配与状态过滤；当前负责人和客户数量清楚显示；查看某人员名下客户；单条/批量选择后指定接收人，填写分配原因。
2. **分配前预览**：显示当前与目标负责人、受影响数量、不可分配原因；有商机/合同/交付等下游责任时，明确进入现有整体交接流程，不能只改客户owner留下悬挂业务。
3. **角色功能矩阵**：中文模块及操作名称；区分查看、新增、编辑、分配、导入/导出与敏感决定；展示依赖和角色基线；保存前预览影响人员。权限依赖必须服务端校验。
4. **人员有效权限**：从人员页可查看当前角色、部门、功能权限及数据范围；不把组织同步身份当作授权。最后管理员、自己降权、未完成审批和交付责任继续受现有保护。
5. **数据范围设置**：先明确本人、本部门、公司三个层级，部门默认不含下级；若提供包含下级、指定部门/人员或客户协作，须有独立选择控件、范围说明、上限及共享服务支持。未实现的选项不显示成可用。
6. **分配与权限历史**：执行人、时间、原因、原值/新值和结果；失败可定位，重复提交不重复执行；历史客户和交易证据不随换负责人被改写。
7. **手机H5**：人员和客户选择能搜索，按钮可操作；表格横向滚动、长表单保留保存/取消；无权限显示明确原因。

## 工程顺序

- A：盘点真实权限点、四角色业务限制、所有客户/业务数据过滤入口，形成“设置项—共享策略—HTTP/Web/MCP—测试”对应表。
- B：将有效权限计算集中到同一服务；扩展身份重检和会话撤销；不允许JSON指定租户/执行人，不让限制型设置意外扩大原有权限。定义功能范围与数据范围的组合规则，避免有菜单无数据或有数据无操作的歧义。
- C：在独立测试帐套完成可保存的角色/人员功能与数据范围配置，再开放对应页面；与原型写接口分离，稳定版本契约、事务、幂等、并发版本与审计齐备。
- D：完成客户分配工作台、批量预览/确认、整体交接入口和人员反查；接收人必须在当前公司、有效且有销售资格。主管不得越权跨部门分配，跨部门由管理员显式执行。
- E：对四种角色、权限收回、人员调岗、客户换主、跨公司、并发、直接URL、导出及MCP逐项验证；正式帐套只操作真实需要的配置，不灌测试客户。

## 必须通过的验收链路

- 管理员给有效销售A分配客户，A可见，未获授权的销售B不可见；返回公海后按公海规则可见；再次领取后原负责人失去原归属带来的权限。
- 主管只能查看/分配权限范围内客户，不能通过猜客户编号、接收人编号或请求体替换公司扩大范围。
- 停用、未核定销售资格或待核定部门人员不能成为不符合组织策略的接收人；已有下游业务不被简单换主绕过交接。
- 收回编辑/导出权限后，旧页面、直接HTTP及智能体均拒绝；可见菜单与实际能力一致。
- 数据范围调整同时改变客户/联系人/跟进/行动/商机/合同/回款报表及导出可见内容；不通过总数、统计或重复提示泄露隐藏客户身份。
- 批量分配失败整体回滚或明确按经过设计的分项事务报告；禁止静默部分成功。并发唯一归属、请求重放、版本冲突和审计均有真实MySQL证据。
- 已有管理员保护、审批交接、交付交接、私有附件和委托智能体撤权测试继续通过。
