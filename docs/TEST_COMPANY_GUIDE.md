# 正式与测试帐套操作说明

本机可建立独立的正式和测试公司帐套。真实公司名称、人员与业务资料只保留在本机：

|用途|显示公司|编码|资料|
|---|---|---|---|
|正式使用|本机配置的真实公司|本机配置|按授权导入的真实资料及业务单据，不随源码公开|
|验证测试|测试帐套|TEST|丰富的合成人员、组织与业务链路，与正式库隔离|

登录页填公司编码和自己的账号。网页头部显示正式/测试标识，手机端也保留；测试帐套使用明显的测试名称，不能把其中金额当作真实经营数据。右上角“切换公司帐套”先撤销当前会话，再进入另一公司登录。

## 组织与角色

测试帐套有管理部、销售中心、其下华东销售部和华南销售部、项目交付部，共5个部门；9个人员。四类角色和独立团队用于验证范围：管理员看公司并管理配置；华东/华南主管各看本部门；销售看自己及公海；老板看经营和审批，不能编辑销售业务。

本机测试用户名包括admin、admin2、manager、manager_south、sales、sales02、sales03、boss、delivery。初始密码与人员口令分别在本机`.local/accounts/TEST-账号说明.txt`和`TEST-测试人员账号.txt`，正式管理员口令在`TINGMENG-账号说明.txt`。这些文件只留本机，不进入GitHub或源码分发包；不在公开文档写入口令。

正式公司不创建虚构员工。可在系统管理建立实际部门和员工、分配四种角色，待真实人员明确后配置实际审批人并发布流程。测试帐套的流程不能自动复制到正式公司，避免把合成审批人带入真实业务。

## 可以复查的测试链路

33客户、27联系人、12线索、24商机、12合同、6订单、6项目、15任务、24期付款计划、8条收款登记、25个审批实例、4条已发布审批流、2个售后工单、24条跟进、24条行动。

- 合同审批：主管核对后老板核准，包含通过、待处理、驳回、批准待签约、草稿等状态。
- 订单审批：老板核准后确认和交付，另有待审批和草稿。
- 项目立项：独立管理员审批；项目含进行中、任务未完成、独立验收完成、拒收后重新开启任务、待审批。
- 通用会签：主管和老板全员确认，含已完成、部分同意、尚待处理的实例。
- 客户：公海领取/退回、主管指定分配、已有业务的整体销售交接，旧销售失去读取权、新销售接手关联销售工作。
- 去重：同名/证照硬拦截、隐藏客户身份保护、共享电话/网站提示；人工、导入和转化复用硬约束。
- 收款：8笔中6笔已复核、2笔草稿，4笔有核销；单笔全额和部分核销、未核销余额与跨期计划分别展示。
- 售后：独立复核关闭和正在处理的工单，保留完整处理记录。

合成金额校验基准：开放管道871500.00、阶段加权预测284100.00、已签合同216000.00、已复核到账45000.00、已核销20400.00、未核销24600.00、当前未收195600.00、逾期15600.00。期间数据按实际业务日期分开，不把核销当成新的到账。账龄会随当前日期变化；本批金额基准对应初始化验证日，后续改测试资料或日期变化后应按记录重新核对。

## 其他安装机器初始化测试资料

先从服务器本机帐套管理页创建编码TEST、用途“测试验证”的空帐套。再在项目根目录执行：

```sh
SMOKE_ALLOW_WRITES=true node scripts/seed-test-company.mjs
node scripts/verify-test-company.mjs
```

自定义端口时设置`CRM_LOCAL_URL=http://127.0.0.1:PORT`。初始化器只能操作明确标记为test且编码TEST的公司，拒绝正式公司；不会清空已有业务。首次只接受空测试公司，分步保存回执以供中断接续；完成后重复执行返回已初始化，不覆盖你后来修改的测试记录。验证器按初始样本核对关系与金额，修改样本后可能不再符合固定基准，这不是自动重置的理由。

自动化CI在临时独立公司库执行同一套链路，并检查重复初始化不增加记录。本机163项关系、财务勾稽、角色范围、跨公司拒绝及正式业务空白检查已通过；初始化包含828次HTTP/业务检查。整体生产验收及真实员工试用仍需继续。
