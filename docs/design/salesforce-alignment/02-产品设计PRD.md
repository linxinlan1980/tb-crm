# 产品设计PRD v1.0

日期2026-11-15；状态设计候选；需求来源为产品负责人本聊天指令、当前源码审查和00来源台账。目标客户暂按B2B项目销售团队设计，实际用户规模、行业规则及验收数据待实施时补齐。

## 1. 目标与范围

完整范围按01矩阵F01—F48管理。先修正在用的业务错误，再实现连续销售操作、过程管理和AI成果，最后扩展经营平台及高级销售能力。成功需以真实任务完成与数据一致性验证，不用菜单数量或代码行数衡量。

不把Salesforce行业云、商业授权生态、内部专有运行时等价为本项目需求。P3完整保留；税务、银行支付、会计处理继续遵循此前“前端演示，暂无功能”的约定，不能因本次对标自动开放。现有本地收款台账独立于银行核验。

## 2. 角色与工作入口

|角色|默认工作|可操作范围|关键限制|
|---|---|---|---|
|销售|今日任务、新线索、待跟进、商机下一步|自己的及被授权协作记录|不自批；不查看未授权同事数据|
|销售主管|团队风险、资源分配、周会、预测审核|职责团队和显式共享范围|跨部门共享需明确授权；不隐式提升财务权|
|老板|目标、预测差距、成交和现金风险|默认只读经营范围|不因看板身份获得全量敏感正文|
|admin|人员、权限、字段、流程、集成和运行|租户内管理权限|管理员不等于业务审批人；不得代替原委托人批准AI建议|

四种登录身份保留。未来商务/财务专岗先通过权限集设计与评审扩展，不能为实现“双人复核”给普通财务人员完整管理员权限。M0保持现有角色行为，M7再迁移权限配置。

## 3. 主线与状态

线索分配→跟进/查重→转客户与联系人→建立商机→阶段推进→报价版本→审批合同→签约→订单/交付→验收→本地收款核销→续费/售后。

- Lead：new→assigned→working→qualified→converted；不合格可disqualified并留原因。线索转化单一事务，明确复用或新建客户/联系人，商机可选；重复请求不重复建档。
- Opportunity：open↔阶段推进；open→won/lost。赢单与合同签约策略显式配置，首批继续从审批后签约触发。closedAt与预计成交日分开。重开必须权限、原因、事件和下游校验，不能简单改回open。
- 销售阶段建议：发现机会→需求确认→方案验证→报价→商务谈判→待签约。won/lost为终结；交付与验收回归项目，不在开放销售管道里继续滚动。历史阶段按映射方案迁移，不能重写历史成交/丢单事实。
- Forecast：period draft→submitted→reviewed→locked；锁定后更正追加revision。类别用Pipeline/Best Case/Commit/Closed/Omitted，中文名可配置。阶段、概率、预测类别分别存储；手工改类别记录理由；单类与累计口径分开。
- Activity：draft→scheduled→completed/cancelled；逾期为派生显示。跟进记录不可悄悄覆盖，纠错留版本。下一步必须明确执行人和计划时间，完成可接续新任务。
- AI suggestion：draft/proposed→approved/rejected/expired→executed/failed；版本变化重新预览；批准不等于执行成功，执行必须回执。

## 4. 核心需求规格

### F01—F03 工作台与检索

登录后按角色显示优先工作，条目包含触发原因、关联记录、负责人/期限和可执行动作。销售可直接完成/改期行动；主管可按团队/周期筛风险并打开商机。刷新保留筛选。搜索按对象与字段权限，空态提供建档入口。引用选择用服务端搜索，不能只提供前100条。保存视图带owner、版本和共享范围；公共视图只有有权者修改。批量动作预览对象数、影响和拒绝原因，重检每条权限。

### F04—F08 客户与活动

客户详情带固定摘要、联系人角色、商机/合同/项目/回款关联和活动时间线；从详情新建子记录自动带入父对象。客户重复时展示候选及匹配依据，合并需预演引用迁移与冲突，已审批单据中的主体历史快照不可被合并重写。

同一联系人可在不同商机中任不同角色；保留现有客户级decisionRole作参考，不自动认为是所有项目的决策人。拜访录入可先保存草稿，再确认客户、商机、正文及下一步。外部邮件会议尚未连接时显示未连接；不伪造已发送或已同步。

### F09—F14 商机、管道、预测

商机详情显示阶段、关键字段、完成指引、参与人、下一步和风险。指引与强制校验分开配置，服务端对页面/批量/API/MCP执行同一校验；错误指出缺失项并提供补齐入口。高级阶段不得因为填写形式字段就自动推断成交真实。

管道查询指定closePeriod、owner/team、状态、类别、风险；所有汇总和列表使用同一查询及权限，返回总量和统计口径。输单从开放管道移出，仍可专门查询。阶段滞留从真实事件算，历史不完整显示未知。历史快照按周期保存，调岗后不能把历史业绩全部算给新负责人。

预测销售本人提交，主管调整需说明且不覆盖原提报。冻结保留周期、币种、维度、记录版本和原始/调整值；迟到数据进入修订。现金回款预测与签单预测分开，不用含税合同额代替收入确认。

### F15—F19 产品报价与合同

产品、价目表有有效期、币种、计量和适用范围；选定价格后存来源与快照。报价版本不可变、只能选择一个当前有效版本，输出文件与审批版本一致。合同签约前核对主体、金额、审批、付款条款和关联商机。

付款条款结构化：固定金额/比例、币种、触发方式（签约/固定日/里程碑）、偏移日、到期约定。总额精确到分且等于合同额，尾差明确归最后一期并展示。里程碑未发生时标记“待触发”，不能生成虚假的已到期日。固定30天全额仅可作为显式演示模板，不作为正式隐式规则。正式旧合同迁移不自动改变已有核销余额，先生成差异报告及修订审批。

续费、增购、减购与终止保留原合同关系和服务权益范围；价格、日期和金额变化不能直接覆盖旧合同。高级订阅按M11专项设计推进。

### F20—F30 配置、报表、治理与自动化

报表字段、过滤、分组、聚合均在许可目录内；用户只能查询可见字段和记录，不接受任意SQL。每指标显示币种、期间、范围、生成时间和公式版本，可钻取到同口径明细。看板默认按当前用户权限计算，禁止通过固定管理员运行身份泄漏数据。

字段定义、业务类型、布局、规则和流程均草稿→预演→发布→停用，引用固定版本。隐藏字段不等于没有读取权限；字段可见、可编辑和业务必填分别校验。公式和自动化使用受限表达式，不执行用户脚本。触发器先写事务内事件/outbox，异步动作有去重、深度限制、失败队列和重放权限。

导入按批次、映射和外部ID处理：先预演，再分块执行；每行可回看结果；重试不重复。客户/联系人/商机/合同/期初余额分别有模板与依赖，已生下游数据不能一键物理回滚。期初金额采用独立迁移事件和对账，不虚造银行收款记录。

### F31—F36 AI与集成

AI面板始终带当前客户/商机上下文、数据来源和权限。先完成三类：拜访转跟进与行动、带来源的客户简报、带证据的商机风险/字段更新建议。未知预算、人物角色、日期不能由模型编造；相对日期需依据用户时区确认。文档和客户文本作为数据，不接受其中的工具执行指令。

模型只生成结构化建议，业务命令负责校验与写入；高影响动作默认人工确认。模型失败可继续手工录入，不阻塞主线。外发邮件/消息单独批准和去重；未连接集成只能保存草稿。

钉钉飞书及邮件日历配置有连接状态、授权范围、最近同步和失败原因；凭证只在服务器安全配置，正文不进GitHub。免登校验企业及账号绑定，回调校验签名、时效和重放，外部离职事件引发撤权而非仅更改页面状态。

## 5. 非功能与未决项

拟验收环境：独立租户、合成测试数据、Node24/MySQL8、桌面与手机。容量、p95、并发和备份RPO/RTO先在M0测基线，再形成明确测试档案；没有测量前不承诺“百万客户”“99.99%”。初始压测数据规模为建议场景，不是当前能力。

待实际企业提供的行业字段、销售阶段、会计边界、测试企业授权、邮件许可与模型部署方式记录为实施参数，不阻断通用设计；真实外部联调必须有这些条件后才能标记通过。未经用户指定，不向客户发送任何消息。
