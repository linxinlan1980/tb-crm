# 验收与发布计划 v1.0

状态：拟验收标准，2026-11-15。本文件没有“测试已通过”的含义。每条A与同编号F对应，完整覆盖01矩阵。

## 1. 验收证据结构

每条记录需求ID/界面ID、实现PR与SHA、环境及数据集、执行角色、前置数据、操作或请求、预期、实际、截图/回执/查询结果、结论与未完成项。通过/失败/阻塞/未执行分开；不能用“有按钮”“CI绿灯”代替业务通过。模型与外部接口使用模拟时必须标模拟。

所有写入能力共同覆盖：权限不足、跨租户、已撤权、无效状态、陈旧版本、同key重放、同key不同参数、并发竞争、晚期故障回滚、失败证据和数据可见范围。变更批准和执行是不同测试点。

## 3. 用户任务验收

拟邀请5位目标销售/主管试用，四角色均覆盖；人数是计划，不是已经完成。使用同一匿名业务样本，分别测“现状基线”和“候选界面”，记录完成率、耗时、错误、求助次数和是否找到下一步。目标阈值在M0基线后与产品负责人锁定，未达成则修复重测。

- T01 新线索→查重→匹配客户联系人→商机，核对关联与来源。
- T02 客户页记录拜访→安排下次行动→工作台完成，手机和桌面各一遍。
- T03 商机补关键人/需求→阶段推进→报价→选择版本→提交审批。
- T04 100万元合同30/40/30→签约→里程碑触发→本地收款复核/核销→纠错。
- T05 主管筛本期风险→识别金额/日期变化→调整下一步→提报预测→老板钻取。
- T06 AI从含歧义日期的拜访记录产生草稿→人工修订批准→执行→查看回执；越权和注入反例必须拒绝。
- T07 管理员导入联系人/商机/历史合同→查错误→重试→核对总额→备份恢复。
- T08 销售离职交接→转移未完事项→撤销会话及代理委托→其他协作人只见新授权范围。

## 4. 模型评测

先建立匿名样本集：真实规则与合成数据结合，覆盖人物重名、否定预算、不确定日期、跨商机、重复拜访、未知资料、文档注入、越权内容。标注事实、来源、允许建议与禁止动作；先做小样本基线再扩大。不编造模型准确率。

不可违反项：无批准不得执行受控写入，越权资料不进入模型上下文，数字/日期和来源一致，模型失败不伪装成功。内容质量与工具执行正确性分别评估；模型/提示/检索版本变化触发相关回归。模型提供商和本地模型适配最终由部署资源与数据策略确定，禁止默认把真实企业数据发给未配置的外部模型。

## 5. 性能和容量验收

建议建立10k客户/50k活动/20k商机的合成数据档案，再按实际企业规模增加；这些是测试输入，不是已证实容量。记录机器CPU/内存/存储、版本、并发、数据分布、缓存、p50/p95、错误率和慢SQL。重点测搜索、候选查询、管道聚合、详情、导入和报表。

M0记录基线后确定页面/API响应预算及超时、批次大小、查询和导出限制。客户端不能依赖前100条或全表加载。AI响应与普通业务接口分别测；可异步任务显示真实进度及取消边界。备份RPO/RTO依赖实际数据量、频率和恢复演练后确定，未测不作承诺。

## 6. 发布门槛与回退

1. PR和测试证据齐备；无未解释的数据/权限/金额缺陷。全部矩阵状态可追踪，P3未完成时不得宣布“完整Salesforce能力已交付”。
2. 生产前备份和隔离恢复验证，升级演练对比行数、金额、权限、附件Hash及会话撤销。
3. 候选包包含精确Git SHA、迁移清单、配置模板、数据模板、安装升级回退说明、角色手册与AI边界。
4. 产品负责人接受具体候选结果后合并/部署；本次设计任务不包含业务上线。
5. 发布后核对运行SHA、迁移状态、四角色登录/首页和关键流程，旧包和新包分别归档，不覆盖旧交付证据。
6. 故障时先停止新增写入/任务或关闭相应feature flag；兼容schema可回退应用；数据已变化按补偿或隔离恢复并人工核对切换，明确数据损失窗口。

真实企业试运行拟先覆盖1个团队、完整一个预测周期并至少一次恢复演练，周期长度按企业月/周节奏确认；没有完成试运行不得使用“商用全面验收通过”。
